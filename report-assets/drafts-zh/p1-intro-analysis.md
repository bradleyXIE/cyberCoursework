# 第一部分：实施

## 1 引言、目标与概述

### 1.1 引言

本报告介绍小组为 MSS Ltd 所做的网络设计。MSS Ltd 有三个部门，分布在同一栋楼的三个楼层。该设计已在 Cisco Packet Tracer 9.0.1 [15] 中实现并测试（文件 CW_CST4562-Implementation.pkt）。设计的目的是在有限预算内满足任务书（brief）对共享服务、部门数据、备份和冗余的要求。报告还包括对 MSS 最严重风险的漏洞分析（vulnerability analysis），以及相应的防御机制和一份维护指南。

### 1.2 目标与具体目标

总体目标是设计、实施并测试一个安全、有弹性且注重成本的网络，为每一位 MSS 员工提供任务书要求的各项服务，并通过测试证明各项安全和冗余措施确实有效。

具体目标如下：

1. 分析场景，将任务书中的要求和假设转化为可衡量的设计需求（第 2 节）；
2. 设计拓扑、VLAN/IP 规划和布线规划，规模按当前用户数确定并留有增长空间（图 00、图 01）；
3. 为所有员工提供 Internet、内网（intranet）、电子邮件和部门数据库访问，并配备独立的备份数据库和归档；
4. 在预算允许的范围内，消除核心、服务器、边缘和 ISP 各层的单点故障（single point of failure）；
5. 实施分层的安全控制，并用 Packet Tracer 测试逐项证明（图 02–14）；
6. 使用合适的工具分析漏洞，说明每个漏洞对应的防御措施，并提出维护计划。

### 1.3 当前场景概述

MSS Ltd 共有 60 台工作站：市场部（Marketing）在 1 楼（20 台），销售部（Sales）在 2 楼（25 台），综合支持部（General Support）在 3 楼（15 台）。各部门主要使用自己的应用程序，并各自保存一个存放本地信息的数据库。不过，有些应用程序会在部门之间传输数据，而且每位员工都必须能够访问每个部门的数据库。所有员工都需要 Internet、内网和电子邮件。任务书假定需要以下内容：用于应用程序和大型数据集的部门服务器、电子邮件和内网服务器、数据库服务器和备份数据库服务器、备份/归档服务器、冗余方案，以及持续的漏洞分析和维护。预算有限，但 MSS 愿意为质量付费。

## 2 当前场景与需求分析

### 2.1 分析

**用户数量与增长。** 每层楼有 15–25 个用户，因此设计在 1 楼和 3 楼各需要一台接入交换机（access switch），2 楼需要两台。销售部需要 25 个端口，超过一台 24 口交换机能提供的数量，因此分到两台交换机上（13 个和 12 个端口）。这样 2 楼还剩 23 个空闲端口，整体约有 40% 的接入端口空闲。每个部门使用一个 /24 子网（可容纳 254 台主机，而目前只有 15–25 台），因此增长不会迫使重新编址。

**规模与拓扑。** 一栋楼里 60 个用户，不值得单独设置汇聚层（distribution layer），那只会增加成本、设备和故障点。由两台多层交换机（multilayer switch）组成的折叠核心（collapsed core）能以较低成本提供设备冗余；日后也可以通过增加接入交换机或一对汇聚交换机来扩展。

**跨部门数据访问。** 所有员工都需要访问每个部门的数据库，因此数据库服务器不能放在各部门的 VLAN 内。它们被放在一个共享的 DATA VLAN 中，所有用户 VLAN 都可以通过 HTTPS 访问（图 06c）。部门之间主机到主机的直接流量被拒绝，只保留 ICMP echo 以便技术支持。这意味着部门之间的数据只能经由部门服务器流动，从而限制了横向移动（lateral movement）。

**可用性。** 每个部门都依赖共享服务器和 Internet。因此，核心、边缘或 ISP 任何一处出故障都会影响整个公司，所以这几层都做了双份。数据的备份副本必须在主服务器故障后依然可用，因此副本库和归档服务器安装在与主服务器不同的机柜和不同的交换机上。

**安全。** 备份数据库和管理平面（management plane）存放着最敏感的资产。用户没有直接访问它们的业务需要，因此它们与用户 VLAN 隔离（图 05、图 12b）。用户都是内部人员且处在共用楼层中，因此接入层需要有防范私接设备（rogue device）、欺骗（spoofing）和 MAC 泛洪（MAC flooding）的控制措施。

**预算。** 在只需要二层和安全功能的地方，使用固定配置的接入交换机。路由、HSRP、DHCP 中继（DHCP relay）和 ACL 集中在两台核心交换机上。配置即代码（configuration as code）降低了维护和重建的成本。

### 2.3 假设

- MSS 位于一栋三层的楼内；如任务书所述，每层一个部门（图 00）。
- 1 楼有一间可上锁的房间可作为安全的服务器机房（主配线间 MDF），配有门禁卡、UPS 和 A/B 两路供电，并有放置两个机柜的空间。每层楼有一个小型楼层配线间（IDF），放置该楼层的一台或几台接入交换机。
- 楼内有两条独立的管道，可走两条垂直主干（riser）路由，分别通往两台核心交换机。
- MSS 可以向两家不同的服务商签订 Internet 线路（ISP-A 为主用，ISP-B 为备用）。在仿真中，它们用路由器表示，使用 RFC 5737 文档地址 [8]。
- 工作站数量以任务书所述为准；预计会有增长，但尚未量化。
- 每个服务器角色用一台单网卡的 Packet Tracer 服务器表示。在生产环境中，会选用双归属服务器。
- 接受并记录了 Packet Tracer 的限制。用 2960-24TT 代替生产环境中的 Catalyst 9200 接入交换机。铜缆千兆上行链路代表拟采用的 OM4 光纤主干。由于不支持 IP SLA/对象跟踪（object tracking），因此使用了浮动静态默认路由（floating static default route，AD 250）。
